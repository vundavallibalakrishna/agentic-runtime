# GRC flows — refreshed proof, 9 Nov 2026 (current HEAD)

A reproducible, **asserting** GRC proof on current `main`, driving the platform's **generic**
document + knowledge tools (no industry code) on GRC-shaped inputs with a real model
(`Qwen/Qwen3-32B` via DeepInfra). It refreshes the 5 Nov run and adds ISO 27001 + CCM fixtures.
Harness: `scripts/grc_proof.py`. Stack: a gateway + api on isolated ports against the reused
`ar-fresh` dependency stack + an isolated `grc_proof` database (nothing shared was touched).

## Headline

**The generic document actions are prompt-driven.** Bound to one generic GRC agent (persona +
instructions + tool bindings — no industry code), the model picks and fires the right action
from a natural-language prompt: `documents.check`/`gaps`/`read` for gap analysis,
`documents.rewrite` for a clause change, `documents.extract` for a value, `knowledge.search`
for the trust library. Verified live across SOC 2, ISO 27001 and CCM. **15/18 asserted checks
passed**; the 3 misses are documented findings below, not flow failures.

## What works well

- **Prompt → generic action** is reliable: every flow invoked the intended `documents.*` /
  `knowledge.*` tool from plain English — no industry-specific routing.
- **No hallucinated coverage**: every deliberately-impossible decoy control (a lunar data
  centre, an orbital failover, a Mars DR site) came back `not_found` via the structured
  `:check`, across all three frameworks.
- **Rewrite** produces a real clause proposal once the clause is pointed at by its anchor.
- **Multi-framework**: the same generic tools handled SOC 2, ISO 27001 and CCM control lists —
  the "standard" is just the document/requirements you supply.

## Findings (not fixed here — fixes need owner approval; none are industry-specific)

- **F1. Narrative gap-table variance.** The gap tools (`check`/`gaps`) fire every time, but the
  agent's *prose* doesn't always render the full "Control | Verdict | Evidence | Gap" table —
  on this run ISO produced it, SOC2/CCM did not (the model said it couldn't build the table).
  Same model-adherence variance seen in the tool-choice gym. The structured `:check` result is
  the reliable surface; the narrative is model-dependent.
- **F2. `knowledge.search` errored (RAG).** Collection creation succeeded, but the agent's
  `knowledge.search` calls returned an error and retrieved nothing — the embedding/vector path
  with the DeepInfra `bge-m3` embedding alias needs verifying in this setup (a `memory_
  embedding_unavailable` warning appeared too). The agent *honestly reported* the failure
  rather than inventing an answer. Gap/rewrite/extract (no embeddings) are unaffected.
- **F3. Extraction quality.** `documents.extract` read the encryption value (AES-256) correctly
  but, on an earlier run, mis-read the log-retention value ("Version 1.0" instead of "90
  days"). Extraction grounding is model-sensitive for values that resemble other fields.
- **F4. Rewrite needs a resolved anchor.** The model cannot reliably turn a clause number
  ("section 2.4") into a passage anchor; passages here are section-level (`p1-s2`). The proof
  resolves the anchor from the policy's passages before the direct rewrite. (Matches the 5 Nov
  note that rewrite is rephrase-only and anchor-driven.)
- **F5. OQ-66 redaction** did **not** corrupt gap evidence on this run — with `en_core_web_sm`
  installed the PII analyzer runs and the gap flow is clean. (The 5 Nov report saw corruption;
  re-confirm per environment.)

## How to run (current HEAD)

Current HEAD removed dev-login (SSO-only, M38b-T05b), so the proof signs in through the real
Keycloak OIDC flow. Capture the session once with the browser helper, then run:

```bash
# 1. deps: a pgvector Postgres + valkey + seaweedfs + opa + keycloak (e.g. the compose deps),
#    plus a gateway + api on isolated ports, an isolated DB, AR_DB_ENCRYPTION_KEYS set,
#    provider kind "openai_compatible", and en_core_web_sm installed (PII analyzer).
# 2. capture a Keycloak session cookie (admin@dev.local / dev-password):
node docs/testing/grc-flows/scripts/grc-login.cjs      # writes /tmp/grc-cookies.json
# 3. run the asserting proof:
AR_GRC_BASE=http://127.0.0.1:3000 AR_GRC_KEY="$(cat .secrets/deepinfra_api_key)" \
  uv run python docs/testing/grc-flows/scripts/grc_proof.py
```

The cert key is read from the environment and never printed.
