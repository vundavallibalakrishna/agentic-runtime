# M2.5 visual checklist

Start from a fresh checkout.

```bash
make bootstrap
make dev AUTO_PORTS=1
```

`make dev` waits until Postgres is healthy, migrates, seeds, then runs the app processes in the foreground. When the default ports are already taken, `AUTO_PORTS=1` moves them and rewrites localhost URLs, including the model gateway (8001) and the system worker (8013). A second start does not move a port this compose project already published.

`make seed` writes the dev tenant, the four users, fake-llm and the assistant into Postgres. The dev API serves chat from memory ([OQ-31](../open-questions.md)). After it starts, `admin@dev.local` already has three example threads. The other roles start with an empty list.

Sign-in password for Keycloak, for every seeded user: `dev-password`. Dev login does not ask for it.

## 1. Sign-in

1. Open the web URL (`http://localhost:3000`, or the port in `AR_PUBLIC_URL`).
2. You land on **Sign in**. The page names Agentic Runtime and lists four buttons: admin, builder, member and approver at `@dev.local`.
3. Choose **Sign in as member@dev.local**. Chat opens. The header shows `member@dev.local`. The conversation list says there are no conversations yet. The welcome offers three starter prompts.
4. Sign out from the account menu. Choose **Sign in as admin@dev.local**. The list shows "Weekly status for the platform", "How the session cookie works" and "What the assistant should feel like".
5. Sign out. Choose **Continue with SSO**. Keycloak asks for the username, then the password (both fields may be on one page). Sign in as `approver@dev.local` / `dev-password`. Chat opens and the header shows that address. The page does not stop on "Update account information" or "HTTPS required".

## 2. Shell

1. The sidebar shows the wordmark, the workspace name **Dev**, and the primary navigation.
2. Items the role cannot use are absent. Approver sees Approvals. Member does not see Users.
3. Tools, Knowledge, Routines, Approvals and Runs show **Soon** and open a short holding page.
4. Collapse the sidebar. The icons remain and the labels are available to a screen reader.
5. Narrow the window to 375 px. Open the menu, go to Chat, and close it.
6. Press ⌘K (Ctrl+K). Type "models" and jump to Models. Press ⌘⇧O. The composer is ready for a new chat.
7. In the account menu set the theme to Dark, then Light, then System. Reload. The choice remains.

## 3. Chat

1. As admin, open "How the session cookie works". The answer is a short explanation and a Python sample with a **Copy** control.
2. Stay on the welcome state (do not open a thread). Choose **Draft a short status update**. The reply streams in the centred column. **Stop** is available while a slow reply is still arriving: send `Please answer slowly`, then **Stop**. **Send** returns.
3. On a finished assistant message, **Regenerate** replaces the answer. **Copy** copies the text.
4. Attach a small text file. The composer shows the file name.
5. Move the thread away from the bottom while a reply streams. The page does not jump. **Jump to latest** returns to the end.
6. Stop the API and reload Chat. An alert explains that chat could not be loaded, with **Try again**.

## 4. Models, users, health, agents

1. Open **Models**. The table includes `fake-llm`. **Simple** shows the provider name. **Advanced** also shows the base URL. The choice persists after reload.
2. Open **Users** as admin. The four seeded people are listed, from the API when Postgres is up and from the seeded directory when it is not.
3. Open **Platform health**. The API status is `ok` while the API is up.
4. Open **Agents**. The page says the assistant is ready in chat.
