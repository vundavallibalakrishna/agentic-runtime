# Public API conventions

Applies to every endpoint under `/api/v1` served by `api` ([spec 01](../03-specs/01-api-bff.md)). The machine-readable contract is `openapi.json`, generated by FastAPI and committed at `services/api/openapi.json` (CI fails if it is stale). The human index of endpoints is [api-catalogue.md](api-catalogue.md).

## 1. Base URL and versioning

- Base path: `/api/v1`. Breaking changes require `/api/v2`; additive changes (new fields, new endpoints, new enum values documented as "open") are allowed in v1.
- Clients must ignore unknown response fields. Enum fields marked *open* may gain values.
- Internal service-to-service endpoints use `/internal/v1` on `api`, and `/internal/v1` or `/v1` on internal services ([internal-apis.md](internal-apis.md)). They are never exposed through the public ingress.

## 2. Authentication

Exactly one of:

| Mechanism | Header / cookie | Who |
|---|---|---|
| Session cookie | `ar_session` (HttpOnly, Secure, SameSite=Lax, Path=/) + `X-CSRF-Token` header on unsafe methods | Web app users (BFF) |
| Bearer OIDC access token | `Authorization: Bearer <JWT>` issued by Keycloak for client `ar-api` | First-party CLIs / integrations using user identity |
| API key | `Authorization: Bearer ark_<prefix><secret>` | Service accounts and personal access keys |
| SCIM token | `Authorization: Bearer scim_<prefix><secret>` | `/scim/v2/*` only |
| Webhook signature | `X-AR-Signature: t=<unix>,v1=<hex hmac-sha256>` | `/api/v1/hooks/*` only |

Resolved into a `Principal` (`user` | `service_account`) with `tenant_id`, permissions and (for users) group ids. Details: [authn-authz.md](../06-security/authn-authz.md).

## 3. Request conventions

- JSON bodies, `Content-Type: application/json; charset=utf-8`. File uploads use presigned PUT URLs (see [spec 13](../03-specs/13-files-artifacts.md)), not multipart, except `POST /api/v1/files:upload` (≤ 25 MiB convenience path).
- Property names in public JSON are camelCase ([ADR-0026](../02-architecture/adr/ADR-0026-public-json-camel-case.md), [principles §1](../00-overview/principles.md#1-api-and-ui-casing)). Python attributes and database columns stay snake_case. A spec sentence that says `dry_run` means the Python attribute; the JSON name is `dryRun`. Models subclass `ApiModel`. Timestamps are RFC 3339 UTC strings with `Z`. IDs are UUID strings (v7).
- Custom actions use the `:verb` suffix on the resource path (Google AIP-136 style): `POST /api/v1/agents/{agent_id}:publish`.
- `PATCH` uses JSON Merge Patch semantics (RFC 7396) on the documented updatable fields only; unknown fields → 422.
- Optimistic concurrency: resources with `etag` return an `ETag` header; `PATCH`/`PUT`/`DELETE` accept `If-Match`. Mismatch → `412 precondition_failed`. Required on agent drafts, policies and skills.
- Idempotency: every `POST` that creates a resource or starts work accepts `Idempotency-Key` (≤ 255 chars). The first response (status + body) is stored in `idempotency_keys` for 24 h; a replay with the same key and same body hash returns the stored response with header `Idempotent-Replayed: true`; same key with a different body → `409 idempotency_key_reused`.
- Request ids: clients may send `X-Request-Id`; otherwise the server generates one. It is echoed in responses, logs and traces.

## 4. Pagination

Cursor-based on all list endpoints:

- Query: `limit` (1 to 200, default 50), `cursor` (opaque string from the previous page).
- Response envelope:

```json
{ "items": [ ... ], "nextCursor": "eyJrIjpbIjIwMjYtMTAtMjBUMDk6MDA6MDBaIiwiMDE5Li4uIl19", "hasMore": true }
```

- The cursor is base64url(JSON `{"k": [<sort key values>], "d": "asc|desc"}`) signed with HMAC (`AR_CURSOR_SECRET`) to prevent tampering; invalid cursor → `400 invalid_cursor`.
- Default sort: `created_at DESC, id DESC` unless the endpoint documents otherwise. `sort` param where supported: `sort=-updated_at`.
- Filters are query params named after fields (`status=published&owner_user_id=...`). Free-text search param is `q`.

## 5. Errors (RFC 9457 Problem Details)

`Content-Type: application/problem+json`

```json
{
  "type": "https://docs.agentic-runtime.dev/errors/validation_failed",
  "title": "Validation failed",
  "status": 422,
  "code": "validation_failed",
  "detail": "definition.model.alias: unknown model alias 'reasonin'",
  "instance": "/api/v1/agents/0192.../versions/draft",
  "requestId": "req_01J...",
  "errors": [ { "loc": ["definition","model","alias"], "msg": "unknown model alias", "type": "unknown_reference" } ]
}
```

Canonical error codes (the `code` field is stable and is what clients switch on):

| HTTP | code | When |
|---|---|---|
| 400 | `bad_request` | Malformed request not covered by validation |
| 400 | `invalid_cursor` | Bad pagination cursor |
| 401 | `unauthenticated` | Missing/invalid credentials or expired session |
| 403 | `forbidden` | Authenticated but lacking permission |
| 403 | `csrf_failed` | Missing/invalid CSRF token |
| 403 | `tenant_suspended` | Tenant status is `suspended` |
| 404 | `not_found` | Resource does not exist **or** is not visible to the caller (never reveal existence) |
| 409 | `conflict` | Unique constraint / state conflict (e.g. slug taken) |
| 409 | `run_in_progress` | Conversation already has an active run |
| 409 | `idempotency_key_reused` | See §3 |
| 409 | `invalid_state` | Action not allowed in the current state (e.g. publish an archived agent) |
| 409 | `plan_limit_reached` | Creating the object would exceed a `PlanLimits` count (`detail` names the limit key, e.g. `max_agents`); disabled plan feature → 403 `forbidden` with `detail` `feature_not_in_plan:<feature>` |
| 412 | `precondition_failed` | ETag mismatch |
| 413 | `payload_too_large` | Body or file exceeds limits |
| 415 | `unsupported_media_type` | File type not allowed |
| 422 | `validation_failed` | Pydantic or domain validation failure |
| 422 | `unknown_reference` | Definition references a non-existent or invisible object |
| 423 | `resource_disabled` | Agent/tool/model kill switch engaged |
| 429 | `rate_limited` | Rate limit exceeded (`Retry-After` header) |
| 429 | `quota_exceeded` | Quota with action `block` exhausted |
| 500 | `internal_error` | Unexpected error (details only in logs) |
| 502 | `upstream_error` | Upstream model/tool/source failure surfaced synchronously |
| 503 | `unavailable` | Dependency down / maintenance |
| 504 | `upstream_timeout` | Upstream timed out |

## 6. Rate limits

Token-bucket per principal and per tenant in Valkey (`ar_common.ratelimit`). Defaults (overridable per plan via `plans.limits.api_rpm`): 600 req/min per user, 6,000 req/min per tenant, 30 message posts/min per user. Headers on every response: `RateLimit-Limit`, `RateLimit-Remaining`, `RateLimit-Reset` (IETF draft semantics).

## 7. Standard resource fields

Every resource representation includes `id`, `createdAt`, `updatedAt` (if the table has it) and, where applicable, `etag` (hex of `sha256(id || updated_at)`), `createdBy` (`{id, displayName}`). The columns remain `created_at`, `updated_at`, `created_by`.

## 8. Streaming

Server-Sent Events, `Content-Type: text/event-stream`. Event schema and resume semantics: [stream-events.md](stream-events.md).

## 9. OpenAPI generation rules

- Every route declares `response_model`, `status_code`, `summary`, `operation_id` (`<module>_<verb>_<noun>`, e.g. `agents_publish_agent`), `tags=[<module>]`, and documented error responses via the shared `ERROR_RESPONSES` dict.
- `make gen` regenerates `services/api/openapi.json`, `packages/api-client` (hey-api), `libs/ar_client` and the stream-event TS types. CI runs `make gen` and fails on diff.
