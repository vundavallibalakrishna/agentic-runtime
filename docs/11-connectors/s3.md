# S3-compatible storage

List, get and put objects on S3 or a compatible endpoint.

**Implementation:** Built
**Category:** Files
**Auth:** basic
**Verification:** Tested on the provider API
**Note:** Proven against SeaweedFS, an S3-compatible reference server run for this milestone. The MinIO image could not be pulled. Not AWS.
**Local rate limit:** 60 calls a minute.
**Provider page:** https://console.aws.amazon.com/iam/home#/users

## Setup

1. On AWS, open https://console.aws.amazon.com/iam/home#/users and create a user, not the account root.
2. Attach a policy limited to one bucket: s3:ListBucket, s3:GetObject and s3:PutObject.
3. Create an access key. The username on the connection is the access key id. The secret is the secret key.
4. Set the region. Leave the endpoint empty for AWS, or set it for MinIO or another compatible service.
5. A put asks for approval. The bucket name is a setting, not a secret.

## Scopes

- `s3:ListBucket`
- `s3:GetObject`
- `s3:PutObject`

## Settings

- Endpoint URL (`endpoint`)
- Region (`region`)
- Bucket (`bucket`)

## Tools

Reads run. Writes (`W2`) wait for approval.

| Tool | Title | Risk | What it does |
|---|---|---|---|
| `s3_list` | List objects | R0 | List objects in the bucket. |
| `s3_get` | Get an object | R0 | Read an object's text. |
| `s3_put` | Put an object | W2 | Write an object's text. |

A 401 tells the person to reconnect. A 403 names the missing permission. A 404 says the item was not found. A 429 includes the provider's retry-after value. List calls follow the provider's next page and stop after three pages or 50 items.
