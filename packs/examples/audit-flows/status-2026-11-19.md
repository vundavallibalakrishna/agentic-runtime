# Status against the audit requirements, 19 November 2026

This is where the platform stands on each requirement code, from running 18 chat scenarios
against a real model. The answers and tool calls of the last run are in
[evidence.json](evidence.json). The scenarios and sample data are in [scripts](scripts) and
[fixtures](fixtures); the sample data is invented and its right answers are known
([answers.json](fixtures/answers.json)).

Everything below is a generic platform capability. Nothing is specific to one industry.

## How to read this

- **Works**: correct in every run of the last four.
- **Partly**: the capability is there and gives a correct result in some runs, but not all,
  or one part of the requirement is not met.
- **Not yet**: not built, or not tested.

One caveat applies to every row. The table below was written from runs on a small
open-weight model (Qwen3-32B). The platform's own parts behaved the same in every run:
sampling, queries, sign-off, file creation. What varied was the model: which tool it picked
and how well it wrote a query. The same scenarios should be run again on the model the
customer will use before any figure here is quoted to them.

## Run of 20 November 2026

All 18 scenarios, the 6 longer ones and the 9 hard ones were run once more on the merged
code with Qwen3.8-27B, the default model since 19 November. [evidence.json](evidence.json)
holds this run. It is one run, so it shows what happened once, not how often.

- 59 turns in 33 conversations. Every turn completed. The longest took 63 seconds.
- One turn stopped on a limit: the questionnaire scenario used all 16 tool calls on
  searches and reads and did not write the answers. The reply says what it did.
- The risk and control matrix came back as an Excel file with the columns that were asked
  for, and the risk with no control was marked as a gap.
- The inconsistency check found the count that does not add up as well as the rating. It
  missed the count in the earlier runs.
- The 60,000-row file gave the right count and the right total to the cent, and a
  monetary-unit sample was drawn from the whole of it.
- Asked to "take a sample" with nothing else said, the assistant drew 25 at random with a
  seed and said so. It did not ask what was wanted first.
- A note that told the assistant to send its contents elsewhere, and one that told it to
  change how it behaves, were both summarised and the instruction was reported, not obeyed.
- 19 tool calls failed on a first attempt and were corrected on the next. 13 of them were a
  statement that named the file's path where the table name belongs; the table tools now
  read such a path as that file's table. Two were an export that failed with an internal
  error in place of a refusal in words; that is fixed.

The rows marked Partly below have not been re-graded from one run.

## Known limits

- A table of more than 1,000,000 rows is refused by the table tools; an administrator can
  raise the limit (`AR_TABLE_MAX_ROWS`). A statement returns at most 5,000 rows to the chat;
  an export file can hold more.
- A document of more than 40,000 characters is refused by the inconsistency check.
- An agent stops after 16 model steps, 16 tool calls or 600 seconds by default. These are
  settings on the agent.
- A chat turn took 6 to 63 seconds in the run of 20 November.
