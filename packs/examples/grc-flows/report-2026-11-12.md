# Document flows end to end, 12 November 2026

Eight document flows were run from an empty agent to a finished answer on a production-mode stack with a real model (`Qwen/Qwen3-32B`). The run is one script, [`scripts/grc_proof.py`](scripts/grc_proof.py), which signs in, uploads the files in [`fixtures/`](fixtures/), builds one agent with the document tools and a knowledge collection, and checks each result. The files and the script are test material. Nothing about governance, risk or compliance is in the product: the flows use the document library, knowledge, agents, routines and the external API.

## Result

The last run passed 46 of 47 checks. The run before it passed 47 of 47. Raw results are in [`evidence-live.json`](evidence-live.json).

| Flow | What it does | Checks | Passed |
|---|---|---|---|
| A | A security policy judged against a control list, by API and by the agent | 11 | 11 |
| B | What changed between two versions of the policy | 3 | 3 |
| C | A vendor's data processing addendum against the standard, and a rewrite a person accepts | 9 | 8 |
| D | A vendor questionnaire answered from a knowledge collection, with citations | 6 | 6 |
| E | Named fields read out of an audit report and a policy | 6 | 6 |
| F | Personal data hidden before a document is shared | 3 | 3 |
| G | The gap report as a Word file a person can download | 3 | 3 |
| H | The gap check on a schedule, and from another system by API | 6 | 6 |

The one miss is in flow C: asked where the vendor's draft is weaker, the agent listed seven clauses and left out the audit right that the vendor's draft does not have. The comparison it read contains that row. Across five runs after the fixes below (four by script, one by hand in the browser) the agent named the missing audit right in four. This is the model's reading, not lost data.

The same contract review was done by hand in the chat screen as the signed-in admin, with the built-in assistant. It called the comparison tool once and listed all eight differences, the missing audit right among them. It took about 90 seconds.

## What the first run found

The first run passed 43 of 47. Six defects were behind the misses and behind what the browser showed. Each is fixed where it was caused, with a unit test.

1. **The model read a short copy of every tool result.** The tool gateway returns the whole result and a 2,048-character preview for the screen. The agent loop gave the model the preview. A comparison of two short contracts lost its last rows. Fix: the model gets the whole result (`tools/agent_loop.py`, `_model_text`). A direct tool call through the external API also returns the whole result.
2. **The prompt cut results at a fixed 1,500 characters and pointed at a tool the agent did not have.** The agent's own settings `context.toolResultMaxTokens` (default 4,000) and `context.compactionThreshold` existed and were not read. Fix: the cut and the summary level follow those settings; `context.retrieve` reads on a part at a time and is offered to any agent once a result is shortened (`loop/context.py`).
3. **Field extraction made up a value.** Asked for a log retention period, it returned "Version 1.0.", the first sentence of a passage that shared a word with the field name, with a confidence of 0.6. Fix: the model is shown the passages that fit the budget and a value is kept only when it and its quote are in a passage word for word; a value the document labels with the field's name is kept without a model; anything else is empty (`documents/grounding.py`).
4. **Reading an anchor that does not exist returned an empty success.** The model guessed an anchor, got nothing back and told the API caller the policy says nothing about multi-factor authentication. Fix: it is an error that names the document's anchors (`documents/library.py`).
5. **One document check froze the API.** A check, comparison, extraction or rewrite called through the API waited on the model on the event loop. While it ran, a plain request took up to 32 seconds. Fix: the six routes wait off the loop (`routers/documents.py`). Measured after the fix: about one millisecond during a check.
6. **Documents were named by their first section.** A markdown file whose title has no text directly under it was titled "1. Subject matter and duration", so the library showed many files with the same name and a comparison could not say which was which. Fix: the first heading names the file, and the comparison text says which document is left and which is right (`documents/extract.py`, `tools/documents.py`).

## Still open

These are recorded in [OQ-134](../../../docs/open-questions.md).

- Checking a document against a rule document read from a table drops the control id from what the model reads and lists the sheet name as a requirement.
- A questionnaire of several questions gets one knowledge retrieval before the turn. In two of the three runs whose answers were kept, the question about the SOC 2 report was answered wrongly or "not found" although the collection holds the report.
- The document library has no delete. Each run of the script leaves its uploads behind.
- A chat turn with all thirty tools offered takes 80 to 100 seconds on this model.

## Second pass, same day

After the first pass was merged, more flows were done by hand in the browser as the signed-in admin with the built-in assistant, and the open items that change answers were fixed. The last full run passed 47 of 47 checks in 244 seconds; the same run took about 420 seconds before.

By hand:

- **Gap analysis in chat.** The first try produced a table without checking the policy: the assistant called the comparison tool on a policy and a control list, then made up the gaps. After the fixes below the same request returned each unmet control with its id, the policy's own sentence and the gap, for example CC7.2: "Security logs are retained for 90 days."
- **Rewrite a person accepts, in the Documents screen.** Asked to shorten the deletion period, the screen showed the old and new sentence, nothing changed until Accept, and the document then showed the new clause.
- **Word report in chat.** The file was made and offered for download. The tool refused the model's table three times before the fourth call was accepted.

Fixed:

1. **A questionnaire is looked up question by question.** One lookup for the whole message returned passages about the main subject only. Each question now brings its own passage, so the SOC 2 report question is answered from the report.
2. **Control ids reach the agent.** A control list kept as a table is read a row at a time, each row named by its id. The file's name is no longer listed as a rule.
3. **A gap shows what the document says.** For a control that is not met, the check now returns the nearest passage.
4. **Tools are described as this release defines them.** An install kept the tool descriptions of the release that first seeded it. They are now refreshed on load, and the document tools say when to use each. A comparison of two unrelated documents points at the right tool.
5. **A check judges its statements at the same time.** A twelve-statement check went from about 30 seconds to about 11.

Still open, in [OQ-136](../../../docs/open-questions.md): a plain agent still tries the comparison tool first in about one gap analysis in three, then corrects itself; a long tool shows nothing on screen until it ends; the library has no delete.

## Run it

Start the stack, then:

```bash
AR_API_URL=http://127.0.0.1:18010 AR_ADMIN_EMAIL=admin@dev.local AR_ADMIN_PASSWORD=dev-password uv run python packs/examples/grc-flows/scripts/grc_proof.py
```

Name flows to run only those, for example `grc_proof.py C E`. The agent and the routine the script makes are archived at the end.
