# Changelog

## Unreleased

Customer database connections:

- A URL parameter that can retarget the socket, read a file, or run a startup command is rejected. That includes `host`, `hostaddr`, `port`, `user`, `password`, `dbname` and `options`. `sslmode` must be a libpq mode, and a repeated parameter is rejected.
- Keyword=value connection strings (`host=... dbname=...`) are rejected. Use a `postgresql://` or `mysql://` URL. `postgresql+psycopg` and `mysql+pymysql` are accepted.
- Creating a connection resolves the host in the API process. A name that does not resolve is rejected then, not at the first query.
- With `AR_EGRESS_CLOSED`, a customer database must use TLS. An omitted `sslmode` becomes `verify-full`. `disable`, `allow` and `prefer` are rejected. `AR_DB_STRICT_TLS` defaults to true, so `require` is rejected too until it is set to false. Before upgrading a closed install, set `AR_CA_BUNDLE` or add `sslrootcert=system` to each DSN. Without one of those, verify-full looks for a home-directory root certificate and the connection fails.
- `sslcert` and `sslkey` are read only from `AR_DB_CERT_DIR/<tenant id>/`. If `AR_DB_CERT_DIR` is unset, client certificates are refused. `sslrootcert=system` and the `AR_CA_BUNDLE` file remain allowed. A relative path, an encrypted key, a world-readable key, or a certificate without its key is rejected.
- `AR_PLATFORM_DB_DENY_HOSTS` and `AR_PLATFORM_DB_DENY_CIDRS` refuse customer connections to the platform database services and pod network, on any port. The Helm chart fills the bundled CloudNativePG `-rw`, `-ro`, `-r` and `-pooler` names, or the StatefulSet service name. Set `cluster.podCIDR` and `cluster.serviceCIDR`; both are copied into `AR_PLATFORM_DB_DENY_CIDRS`. A malformed CIDR stops the process. Deny names are resolved once and cached. Until every name has resolved at least once, customer dials fail with that reason. A later lookup failure keeps the last addresses. `/readyz` stays ready and reports the miss under `degraded`. The gauge is `ar_platform_db_deny_unresolved`.
- Database role passwords are `AR_DB_OWNER_PASSWORD`, `AR_DB_APP_PASSWORD`, `AR_DB_PLATFORM_PASSWORD` and `AR_DB_READONLY_PASSWORD` in the install secret (`secrets.existingSecret` or the chart secret). Helm does not generate them, and a render with an empty, placeholder, or role-name value fails when the chart creates the secret. Installs with `secrets.create: false` are refused at startup of the API, Alembic and bootstrap in staging and production. No application role is `SUPERUSER`. `ar_owner` has `LOGIN` and `BYPASSRLS` only. `ar_platform` has `BYPASSRLS`. `ar_app` and `ar_readonly` do not. The image superuser installs `vector` and the other extensions, and creates the extra databases, before Alembic. `ar_owner` is not a member of the other roles and is not granted them.
- **Upgrade.** A database created by the previous chart still has `ar_owner` as `SUPERUSER`. The old StatefulSet image user is `ar_app` with password `ar-install-db`. The old compose image user is `ar_owner`. Init scripts do not run again on an existing volume. The chart writes the same bytes to `<release>-secrets` and to a pre-install,pre-upgrade hook Secret `<release>-secrets-hook` at weight -20. The hook name is different so it does not collide with the release object. `reconcile-roles` (weight -10) and `migrate` (weight -5) read the hook Secret with `secretKeyRef`. Bootstrap runs after the release Secret is updated and reads that one. The hook connects as `postgres.superuserUsername` / `postgres.superuserPassword`, which is the login that works today and is not checked as an application password, and sets the four new role passwords. After that run, point `postgres.superuserUsername` at the image `postgres` role: the application role used for the one-time login is no longer a superuser. Compose uses `AR_DB_SUPERUSER_USER` (default `postgres`) for that login. `make migrate` runs the same command. `AR_DB_RECONCILE=skip` (or `external` or `cnpg`) is the only successful skip; a remote URL without `POSTGRES_HOST` fails. `ar_owner` is not granted the other roles. A bundled CloudNativePG install with `secrets.create: false` fails `helm template` until `postgres.existingRoleSecrets` is true and the four `<release>-db-role-ar-*` secrets exist. `helm upgrade --no-hooks` installs the release Secret and does not run the hooks.
- `airgap.isolatePlatformDb` limits platform-database egress to the CNPG pooler, the StatefulSet pods, or `postgres.externalCidrs`. That path is open to `api`, `runtime-worker`, `mcp-gateway`, `sandbox-manager`, `system-worker`, `ingest-worker`, `temporal`, and the `migrate` and `bootstrap` jobs. CNPG pooler pods may reach instance pods on 5432. Instance pods may reach each other on 5432 and 8000, and the operator namespace may reach them on 8000. `api`, `runtime-worker` and `mcp-gateway` also open `airgap.tenantDbPorts` (default 5432 and 3306) to `airgap.tenantDbCidrs`. A wide CIDR excludes `cluster.podCIDR` only when the CIDR contains it. `postgres.externalCidrs` is granted even when isolation is off. An external database with isolation on and no CIDR fails the chart render.
- Underscores are allowed in a customer database hostname because internal DNS and libpq accept them.
- `AR_DB_STRICT_TLS_FLOOR` defaults to `verify-full`, so closed egress also rejects `verify-ca`. Set it to `verify-ca` only for a server addressed by an IP literal. A hostname stays on `verify-full`. `require` stays rejected while `AR_DB_STRICT_TLS` is true.
- A customer-database dial tries at most `AR_DB_MAX_ADDRESSES` (default 4) addresses and stops after `AR_DB_CONNECT_DEADLINE_S` (default 15). The host must be an IP literal or an RFC 1123 name.
- There is no migration.

## 1.0.0

First shippable release of Agentic Runtime.

- Helm umbrella chart for single-tenant and SaaS, with dev, small, large, load-test, external and air-gap presets.
- Bundled or external Postgres (CloudNativePG or a dev StatefulSet), Valkey, Temporal, Keycloak, OpenBao and SeaweedFS. Qdrant stays off unless enabled.
- Backup CronJobs, a fixture restore drill, and Locust scenarios for the performance budgets.
- Rolling upgrades with a migrate hook, PodDisruptionBudgets and optional Temporal worker build ids.
- Air-gap image list and mirror script.
- Release workflow packages the chart from a version tag.

The product behaviour through M14 (chat, agents, tools, policy, sandboxes, knowledge, memory, skills, routines, channels, quotas, evals and assurance) is included.
